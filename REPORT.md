# REPORT · отчёт о денежном потоке

## Что исправлено в расчёте и почему

Сверял API с независимым расчётом прямо из `synthetic.json` (отдельный скрипт без Django). До исправления апрель по сети давал платежи 1 111 301,00 ₽ вместо 1 099 190,00 ₽, у студии S02 — 47 ТД-покупателей вместо 9.

| # | Ошибка в `service.py` | Последствие | Исправление |
|---|---|---|---|
| 1 | Границы окна строились в UTC (`timezone.utc`) | Операция `2026-03-31T21:30Z` (1 апреля 00:30 МСК) выпадала из апреля, а `30.04 21:00Z…` (уже 1 мая МСК) попадала в апрель | Границы — полночь по `Europe/Moscow`: `[первый день 00:00; день после последнего 00:00)` |
| 2 | Платежи не дедуплицировались по `transaction_id` (только возвраты) | Повторная доставка удваивала платёж | Одна запись на `transaction_id` и для платежей, и для возвратов |
| 3 | `summary.td_buyers` считался по всей сети, без фильтра студии | При выборе студии показывались покупатели всей сети | Все KPI считаются одной функцией по одному набору транзакций |
| 4 | Дедупликация шла после фильтра окна | Повтор, доставленный после границы окна, засчитался бы ещё раз в следующем окне | Транзакция относится к моменту **первой успешной** доставки; в окно попадает, только если этот момент в окне |

Также: фильтр студии перенесён в SQL (`order__studio_id`), `operations[].occurred_at` теперь отдаётся с московским смещением `+03:00` (тот же момент времени, но читается без перевода; фронт всё равно форматирует в `Europe/Moscow`).

**Допущения.** (1) Если у транзакции есть и неуспешная, и успешная доставка, учитывается успешная. (2) Сумма и вид повторных доставок одинаковы (в наборе так и есть: 2 повтора, полностью идентичные); берётся первая. (3) Таблица студий при выборе студии показывает только её, с кнопкой «← Вся сеть». (4) В итоговой строке таблицы студий ТД-покупатели — уникальные по сети (со сноской, почему меньше суммы строк).

## Что реализовано

- **Backend**: исправленный расчёт; валидация (формат, порядок, ≤93 дня, переполнение даты, неизвестная студия → 400 с `error`) сохранена.
- **Frontend**:
  - пять KPI; «Платежи» и «Возвраты» раскрывают список операций (дата/время МСК, транзакция, заказ, клиент, студия, продукт, сумма) с итогом и проверкой «совпадает с карточкой»;
  - дневной SVG-график: подсказка при наведении, выбор дня стрелками ←/→/Home/End с фокусом на графике, раскрываемая таблица точных значений;
  - таблица студий с итогом; клик по студии применяет общий фильтр, есть возврат ко всей сети;
  - фильтры с кнопкой «Показать», быстрые периоды, проверка дат на клиенте (те же правила, что в API), подпись текущего периода («1 апреля 2026 г. — 30 апреля 2026 г. · 30 дней · Студия 02»), подсказка о непримененных изменениях;
  - состояния загрузки, ошибки с «Повторить» (повторяет последний **применённый** выбор), отдельное пустое состояние;
  - защита от гонок: предыдущий запрос отменяется через `AbortController`, а поздний ответ или ошибка устаревшего запроса игнорируются;
  - адаптив до 390 px без горизонтального скролла страницы (таблицы и график прокручиваются внутри блоков), подписи полей, фокус-стили, `aria-live`/`aria-expanded`.

## Тесты и какое правило защищает каждый

Backend (`reporting/tests.py`, 15 тестов; 4 исходных оставлены):
- `test_task_example_redelivery_and_partial_refunds` — пример из ТЗ: повтор доставки не удваивает деньги, частичные возвраты — разные операции, отрицательный поток.
- `test_refund_redelivery_counted_once` — уникальность по transaction_id для возвратов.
- `test_redelivery_after_window_does_not_move_money_again` — повтор после границы окна не создаёт нового платежа.
- `test_failed_operations_excluded`, `test_failed_then_success_delivery_counts_success` — неуспешные не входят.
- `test_moscow_window_and_daily_grouping` — окно и дни по Москве, смещения `Z` и `+03:00`.
- `test_refund_of_earlier_payment` — возврат в окне при оплате до окна; возврат не отменяет оплату.
- `test_studio_by_order_owner_and_unique_buyers` — студия по владельцу заказа, ТД-покупатели в рамках студии, сумма студий = сеть для денег, уникальные сети ≤ сумме студий.
- `test_period_validation` — 93 дня можно, 94 нельзя; неверные/несуществующие даты и переполнение → 400.
- `SeedDatasetTests` — регрессия на учебном наборе (значения сверены с независимым расчётом) и согласованность «карточка = дни = студии = операции» для сети и каждой студии.

Проверил, что тесты ловят исходные ошибки: на исходном `service.py` падают 6 из 11 новых.

Frontend (`tests/rules.test.ts`, 8 новых + 3 исходных): поздний ответ/ошибка старого запроса не перезаписывает новый, старый запрос отменяется; «Повторить» берёт последний применённый выбор; проверка периода (ровно 93 дня, перевёрнутый, длинный, несуществующая дата); время операции на границе месяца — по Москве; подпись периода; отрицательные суммы с копейками.
